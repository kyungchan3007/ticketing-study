# US-04 예매 요청(결제 대기)

**사용자로서** 내가 잡은 좌석의 예매를 요청하고 싶다. **그래야** 결제가 끝나면 그 좌석이 내 예매가 된다.

공통 예시 데이터와 오류 형식은 [PRD](../PRD.md) 3·5·9절을 따른다. 엔드포인트와 응답 필드는 API 계약에서 정한다. 테스트 시각은 주입한다. 예매 요청에는 `X-User-Id`(없으면 401)와 `Idempotency-Key`(없으면 400)가 필요하다. 좌석맵 확인은 헤더 없이 한다.

예매 요청은 결제 대기(`PENDING`) 예매를 만들 뿐 좌석을 팔지 않는다. 좌석이 SOLD가 되는 것은 모의 결제사의 성공 콜백이 홀드 만료 전에 처리될 때다([US-05](US-05-payment-callback.md)). 아래에서 "성공 콜백으로 SOLD"는 US-05의 콜백 요청을 뜻한다.

**규칙:** 예매 요청은 그 좌석을 홀드한 사용자가, 그 홀드가 만료되기 전에만 할 수 있다.

## 인수 조건

### AC-04-1 만료 전 본인 홀드로 예매 요청: 결제 대기
- **Given** 시각 `T0`에 `u1`이 `A1`을 홀드했다
- **When** 시각 `T0 + 4분 59초`에 `u1`이 `Idempotency-Key: k1`로 `A1` 예매를 요청한다
- **Then** 응답은 2xx이고 예매 상태는 `PENDING`, `booking_id`가 있다
- **And** 좌석맵에서 `A1`은 아직 `HELD`다(SOLD가 아니다)

### AC-04-2 만료된 홀드로는 예매를 요청할 수 없다
- **Given** 시각 `T0`에 `u1`이 `A1`을 홀드했다
- **When** 시각 `T0 + 5분`(경계값)에 `u1`이 `A1` 예매를 요청한다
- **Then** 응답은 409이고 본문은 `{"code": "HOLD_EXPIRED", "message": <문자열>}`이다
- **And** 시각 `T0 + 5분 1초`에 다시 요청해도 409 `HOLD_EXPIRED`다
- **And** 예매는 만들어지지 않는다. `A1`은 SOLD가 아니고, 이어서 `u2`가 `A1`을 홀드하면 2xx로 성공한다

### AC-04-3 만료 후 다른 사람이 다시 잡은 좌석
- **Given** 시각 `T0`에 `u1`이 `A1`을 홀드했다
- **And** 시각 `T0 + 6분`에 `u2`가 `A1`을 홀드했다
- **When** 시각 `T0 + 7분`에 `u1`이 처음 홀드로 예매를 요청한다
- **Then** 응답은 409 `HOLD_EXPIRED`다
- **And** 이어서 `T0 + 7분`에 `u2`가 예매를 요청하면 2xx `PENDING`이고, 성공 콜백이 오면 `A1`은 `SOLD`다

### AC-04-4 남이 산 좌석의 예매 요청
- **Given** `u1`이 `A1`을 홀드하고 예매를 요청한 뒤 성공 콜백이 와서 `A1`은 SOLD다
- **When** `u2`가 `u1`의 홀드로 예매를 요청한다
- **Then** 응답은 409이고 본문은 `{"code": "SEAT_ALREADY_SOLD", "message": <문자열>}`이다

### AC-04-5 같은 사람의 동시 예매 요청: 예매는 하나 (Q1·Q13)
- **Given** 시각 `T0`에 `u1`이 `A1`을 홀드했다
- **When** 시각 `T0 + 1분`에 `u1`이 같은 홀드로 서로 다른 `Idempotency-Key` 10개를 써서 예매를 동시에 요청한다
- **Then** 10건 모두 2xx이고 `booking_id`가 모두 같다
- **And** 그 홀드의 예매는 정확히 1개(`PENDING`)다

### AC-04-6 홀드부터 예매 요청까지 경쟁
- **Given** `A1`이 AVAILABLE이고 시각은 `T0`로 고정이다
- **When** 사용자 `u1` … `u10`이 각자 "`A1` 홀드 → 성공하면 바로 예매 요청"을 동시에 실행한다
- **Then** 예매 요청 2xx는 정확히 1건이다
- **And** 그 1건의 사용자는 홀드 2xx를 받은 사용자와 같다
- **And** 그 예매에 성공 콜백이 오면 `A1`은 `SOLD`다

### AC-04-7 사용자 헤더 없음
- **Given** 시각 `T0`에 `u1`이 `A1`을 홀드했다
- **When** `T0 + 1분`에 `X-User-Id` 헤더 없이 `A1` 예매를 요청한다
- **Then** 응답은 401이고 본문은 `{"code": "UNAUTHORIZED", "message": <문자열>}`이다
- **And** `A1`은 여전히 `HELD`이고 예매는 만들어지지 않는다. 이어서 `u1`의 예매 요청은 2xx다

### AC-04-8 다른 사용자의 홀드로는 예매를 요청할 수 없다 (Q3)
- **Given** 시각 `T0`에 `u1`이 `A1`을 홀드했다
- **When** 시각 `T0 + 1분`에 `u2`가 `X-User-Id: u2`로 `u1`의 홀드 예매를 요청한다
- **Then** 응답은 403이고 본문은 `{"code": "FORBIDDEN", "message": <문자열>}`이다
- **And** 좌석맵에서 `A1`은 여전히 `HELD`이고 예매는 만들어지지 않는다
- **And** 이어서 `T0 + 1분`에 `u1`의 예매 요청은 2xx `PENDING`이다

### AC-04-9 홀드 없이는 예매를 요청할 수 없다 (Q4)
- **Given** `A1`이 AVAILABLE이고 아무도 홀드하지 않았다
- **When** `u1`이 없는 `hold_id`로 예매를 요청한다
- **Then** 응답은 404이고 본문은 `{"code": "NOT_FOUND", "message": <문자열>}`이다
- **And** 좌석맵에서 `A1`은 여전히 `AVAILABLE`이다

### AC-04-10 같은 키로 다시 보내면 같은 응답
- **Given** 시각 `T0`에 `u1`이 `A1`을 홀드했고, `T0 + 1분`에 `Idempotency-Key: k1`로 예매를 요청해 `PENDING` 예매를 받았다
- **When** 시각 `T0 + 2분`에 `u1`이 같은 홀드, 같은 키 `k1`로 다시 요청한다
- **Then** 응답 상태 코드와 본문이 처음과 같다(같은 `booking_id`, `PENDING`)
- **And** 그 홀드의 예매는 정확히 1개다

### AC-04-11 이미 팔린 예매를 산 사람이 다시 요청하면 같은 예매 (Q1·Q13)
- **Given** `u1`이 `A1`을 홀드하고 키 `k1`로 예매를 요청한 뒤 성공 콜백이 와서 예매는 `PAID`, `A1`은 SOLD다
- **When** 홀드 만료 뒤인 `T0 + 10분`에 `u1`이 같은 홀드로 새 키 `k2`를 써서 예매를 요청한다
- **Then** 응답은 2xx이고 같은 `booking_id`, 상태 `PAID`다
- **And** 예매는 여전히 1개다

### AC-04-12 Idempotency-Key 없음
- **Given** 시각 `T0`에 `u1`이 `A1`을 홀드했다
- **When** `u1`이 `Idempotency-Key` 헤더 없이 예매를 요청한다
- **Then** 응답은 400이고 본문은 `{"code": "VALIDATION_ERROR", "message": <문자열>}`이다
- **And** 예매는 만들어지지 않는다

### AC-04-13 같은 키를 다른 홀드에 쓰면 409
- **Given** `u1`이 `A1`과 `A2`를 각각 홀드했고, `A1` 홀드로 키 `k1` 예매를 요청했다
- **When** `u1`이 `A2` 홀드로 같은 키 `k1`을 써서 예매를 요청한다
- **Then** 응답은 409이고 본문은 `{"code": "IDEMPOTENCY_KEY_REUSED", "message": <문자열>}`이다
- **And** `A2` 홀드의 예매는 만들어지지 않는다

### AC-04-14 너무 긴 Idempotency-Key
- **Given** 시각 `T0`에 `u1`이 `A1`을 홀드했다
- **When** `u1`이 256자 키(또는 3000자 키)로 예매를 요청한다
- **Then** 응답은 400이고 본문은 `{"code": "VALIDATION_ERROR", "message": <문자열>}`이다(500이 아니다)
- **And** 예매는 만들어지지 않는다. 255자 키로는 2xx `PENDING`이다

### AC-04-15 다른 사용자가 같은 키를 써도 섞이지 않는다
- **Given** `u1`이 `A1`, `u2`가 `A2`를 홀드했다
- **When** 둘 다 같은 키 `k1`로 각자의 홀드에 예매를 요청한다
- **Then** 둘 다 2xx `PENDING`이고 `booking_id`가 서로 다르며, 각 예매의 사용자·좌석은 자기 것이다
- **And** `u1`이 `k1`로 다시 보내면 `u1`의 예매를, `u2`가 다시 보내면 `u2`의 예매를 돌려받는다

### AC-04-16 너무 긴 사용자 ID (Q10 일부)
- **Given** `A1`이 AVAILABLE이다
- **When** 256자(또는 압축되지 않는 3000자) `X-User-Id`로 `A1` 홀드나 예매를 요청한다
- **Then** 응답은 401이고 본문은 `{"code": "UNAUTHORIZED", "message": <문자열>}`이다(500이 아니다)
- **And** 홀드·예매는 만들어지지 않는다. 255자 `X-User-Id`로는 홀드 2xx, 예매 요청 2xx `PENDING`이다

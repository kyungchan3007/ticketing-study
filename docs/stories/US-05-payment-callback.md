# US-05 모의 결제 콜백

**모의 결제사로서** 결제 결과(성공·실패)를 서버에 알리고 싶다. **그래야** 성공한 결제만 좌석 판매로 이어지고, 같은 결과를 여러 번 보내도 돈과 좌석은 한 번만 반영된다.

공통 예시 데이터와 오류 형식은 [PRD](../PRD.md) 3·5·9절을 따른다. 엔드포인트와 필드 이름은 API 계약에서 정한다. 테스트 시각은 주입한다. 콜백에는 `X-User-Id`가 필요 없다. 콜백 본문의 결과는 `SUCCEEDED` 또는 `FAILED`다(모의 결제는 둘 다 흉내 낼 수 있다, Q11).

**규칙**
- 성공 콜백은 처리하는 순간의 서버 시각이 홀드 만료 전이고, 좌석의 현재 홀드가 그 예매의 홀드이며, 좌석이 아직 팔리지 않았을 때만 좌석을 SOLD로 만든다(예매 `PAID`). 그 밖에는 좌석을 바꾸지 않고 예매를 `REFUND_REQUIRED`로 기록한다.
- 실패 콜백은 예매만 `FAILED`로 만들고 홀드는 그대로 둔다.
- 끝난 예매(`PAID`, `FAILED`, `REFUND_REQUIRED`)에 콜백이 또 오면 아무것도 바꾸지 않고 지금 상태를 2xx로 돌려준다.

공통 준비: 시각 `T0`에 `u1`이 `A1`을 홀드하고, `T0 + 1분`에 예매를 요청해 `PENDING` 예매 `b1`을 받았다(아래 "공통 준비").

## 인수 조건

### AC-05-1 만료 전 성공 콜백: 좌석이 팔린다
- **Given** 공통 준비
- **When** 시각 `T0 + 4분 59초`에 `b1`의 성공 콜백이 온다
- **Then** 응답은 2xx이고 예매 상태는 `PAID`다
- **And** 좌석맵에서 `A1`은 `SOLD`다

### AC-05-2 만료 정각·뒤의 성공 콜백: 팔지 않고 환불 필요
- **Given** 공통 준비
- **When** 시각 `T0 + 5분`(경계값)에 `b1`의 성공 콜백이 온다
- **Then** 응답은 2xx이고 예매 상태는 `REFUND_REQUIRED`다
- **And** 좌석맵에서 `A1`은 `AVAILABLE`이다(SOLD가 아니다). 이어서 `u2`가 `A1`을 홀드하면 2xx다
- **And** 시각 `T0 + 5분 1초`에 처음 성공 콜백이 와도 같다(`REFUND_REQUIRED`, `A1`은 SOLD가 아니다)

### AC-05-3 다른 사람이 다시 잡은 뒤 늦은 성공 콜백
- **Given** 공통 준비
- **And** 시각 `T0 + 6분`에 `u2`가 `A1`을 홀드했다
- **When** 시각 `T0 + 7분`에 `b1`의 성공 콜백이 온다
- **Then** 예매 `b1`은 `REFUND_REQUIRED`다
- **And** 좌석맵에서 `A1`은 `HELD`이고 `u2`의 홀드다(이어서 `u2`의 예매 요청은 2xx다)

### AC-05-4 실패 콜백: 예매만 실패, 홀드는 남는다
- **Given** 공통 준비
- **When** 시각 `T0 + 2분`에 `b1`의 실패 콜백이 온다
- **Then** 응답은 2xx이고 예매 상태는 `FAILED`다
- **And** 좌석맵에서 `A1`은 `HELD`이고, `u2`가 `A1`을 홀드하면 409 `SEAT_ALREADY_HELD`다
- **And** 시각 `T0 + 3분`에 `u1`이 같은 홀드로 새 키를 써서 예매를 요청하면 2xx이고 `b1`과 다른 새 `PENDING` 예매가 생긴다. 그 예매의 성공 콜백이 `T0 + 4분`에 오면 `A1`은 `SOLD`다
- **And** 새 예매 요청 직후 그 좌석의 예매는 `FAILED` 1개(`b1`)와 `PENDING` 1개다

### AC-05-5 같은 콜백이 두 번 오면 한 번만 반영
- **Given** 공통 준비, 시각 `T0 + 2분`에 `b1`의 성공 콜백이 와서 `PAID`다
- **When** 시각 `T0 + 3분`에 `b1`의 성공 콜백이 또 온다
- **Then** 응답은 2xx이고 예매 상태는 `PAID` 그대로다
- **And** `A1`은 `SOLD`이고, 그 좌석의 `PAID` 예매는 정확히 1개다

### AC-05-6 끝난 예매에 다른 결과가 와도 바뀌지 않는다
- **Given** 공통 준비, `T0 + 2분`에 `b1`의 성공 콜백이 와서 `PAID`다
- **When** `T0 + 3분`에 `b1`의 실패 콜백이 온다
- **Then** 응답은 2xx이고 예매 상태는 `PAID` 그대로, `A1`은 `SOLD`다
- **And** 반대로 실패 콜백(`FAILED`) 뒤에 성공 콜백이 와도 `FAILED` 그대로이고 좌석은 팔리지 않는다

### AC-05-7 같은 성공 콜백이 동시에 여러 번: 실제 서버
- **Given** 실제 서버(여러 워커)와 실제 시계에서 `u1`이 `A1`을 홀드하고 예매를 요청해 `PENDING` 예매를 받았다
- **When** 그 예매의 성공 콜백 20건이 동시에 온다
- **Then** 20건 모두 2xx이고 응답의 예매 상태는 모두 `PAID`다. 5xx는 0건이다
- **And** `A1`은 `SOLD`이고 그 좌석의 `PAID` 예매는 정확히 1개다
- **And** 좌석 여러 개(예: 5석)에서 각 좌석마다 같은 성공 콜백 여러 건을 동시에 보내도 좌석마다 `PAID` 1개·SOLD이고 5xx는 0건이다
- **And** 이 테스트는 3번 연속 통과해야 통과로 본다

### AC-05-8 없는 예매의 콜백
- **When** 없는 `booking_id`로 성공 콜백이 온다
- **Then** 응답은 404이고 본문은 `{"code": "NOT_FOUND", "message": <문자열>}`이다

### AC-05-9 콜백 결과 값 오류
- **Given** 공통 준비
- **When** 결과가 없거나 `SUCCEEDED`·`FAILED`가 아닌 콜백이 온다
- **Then** 응답은 400이고 본문은 `{"code": "VALIDATION_ERROR", "message": <문자열>}`이다
- **And** 예매 `b1`은 `PENDING` 그대로다

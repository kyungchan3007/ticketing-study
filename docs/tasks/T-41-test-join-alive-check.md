# T-41 (test) 강제 겹침 테스트 — join 뒤 스레드 생존 검사

## 배경
review의 T-32·T-39 낮음 지적이다. `tests/api/test_us04_confirm_booking.py`의 `test_us04_ac04_13_same_key_two_seats_overlap_forced`(218~263줄)는 finally에서 `t.join(timeout=30)`만 하고, 스레드가 아직 살아 있는지는 검사하지 않는다(259~260줄). 요청이 멈추는 회귀가 생기면 다음과 같이 된다.
- 이 테스트가 끝나지 않은 요청을 알리지 못한다. 대신 `results`가 비어서 엉뚱한 assertion 메시지로 실패하거나 통과처럼 보일 수 있다.
- 살아 있는 스레드와 DB 세션이 남아 다음 테스트의 reset을 막을 수 있다.

같은 파일의 공통 도우미(`tests/api/conftest.py` 223줄, 247줄)는 이미 `assert not ...is_alive()`로 검사한다. 같은 방식으로 맞춘다.

## 할 일
1. join 뒤에 두 스레드 모두 끝났는지 검사하고, 살아 있으면 분명한 메시지로 실패하게 한다(예: "잠금을 푼 뒤 30초 안에 요청이 끝나지 않았다"). 결과 검사(`got == ...`)보다 먼저 한다. 단, finally 안에서 다른 예외(겹치지 않음 AssertionError)를 덮지 않도록 한다.
2. 테스트의 기대값(200 PENDING 1건, 409 IDEMPOTENCY_KEY_REUSED 1건, k1 줄 1개)과 다른 테스트는 바꾸지 않는다. `tests/`만 수정한다. 서버 코드는 고치지 않는다.
3. 이 테스트를 단독으로 5번 돌리고, 전체 `uv run pytest`도 돌린다.
4. 해시를 기록한 뒤 바꾸는 것이므로, 끝나면 lead에게 알린다(lead가 해시를 다시 기록한다).

# T-09 (test) 트래픽 계산 테스트를 T-08 리뷰 반영 공식으로 고치기 — 실패(FAIL)

## 바뀐 공식 (`docs/capacity.md` 2절 G3·G6, 3.2절 표와 설명, 이미 갱신됨)
- 순번 확인(폴링): 요청 수 `Wsum / P + (U − N)`, 기간 `T + P`, 평균 초당 `(Wsum / P + (U − N)) / (T + P)`. 최대 초당은 그대로 `(U − R × A) / P`.
- API 합계: 요청 수는 다섯 API 행 요청 수의 합(폴링 변경이 반영됨), 기간 `T + P`, 평균 초당 = 요청 수 합 / (`T + P`). 최대 초당은 그대로.
- 나머지 행, `N`, `T`, 적용 조건, `compute()` 반환 형태는 바뀌지 않았다. 반환값 `duration_s`(최상위)는 여전히 `T`다.
- G3(확인 시점이 고르게 퍼짐)과 API 합계 최대의 "상한" 설명은 문장만 바뀌었고 계산은 그대로다.

## 할 일
1. `tests/capacity/test_capacity.py`에서 위 공식으로 바뀌는 기대값(기본값과 입력 변경 케이스 모두)을 고친다. 기대값은 공식에서 직접 다시 계산한다.
2. 매진 안내 응답을 따로 확인하는 테스트를 하나 넣는다: 폴링 요청 수 − `Wsum / P` = `U − N`. `N = U`인 경우(매진 없음)에는 0이다.
3. `tests/`만 수정한다.

## 완료 기준
- 아직 옛 공식인 `scripts/capacity.py`로 `uv run pytest tests/capacity`가 실패(FAIL)한다. 실패한 테스트가 바뀐 기대값(폴링·API 합계의 요청 수·기간·평균) 때문인지 확인한다.
- lead에게 보고: 바꾼 테스트, 테스트 개수, 실패 출력 마지막 줄과 이유, 새로 계산한 기본값 기대치(폴링·API 합계의 요청 수·기간·평균·최대). 보고하고 멈춘다.

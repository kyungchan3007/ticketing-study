# T-11 (test) 매진 안내 기간 조건부로 테스트 수정 — 실패(FAIL)

## 배경
T-10 리뷰 #4(중간): 폴링·API 합계 기간을 무조건 `T + P`로 잡아, 남은 대기자가 없는 `N = U` 경우에도 기간이 `P`만큼 늘어난다. 테스트도 그 값(예: S=1e9에서 5,005초)을 기대하고 있다.

## 바뀐 공식 (`docs/capacity.md` 3.2절, 이미 갱신됨)
- `Pn` = `P` (`U − N > 0`일 때), 0 (`N = U`일 때).
- 폴링: 기간 `T + Pn`, 평균 `(Wsum / P + (U − N)) / (T + Pn)`. API 합계: 기간 `T + Pn`, 평균 = 요청 수 합 / (`T + Pn`).
- 기본값처럼 `U − N > 0`인 경우는 T-09와 같다(630초).

## 할 일
1. `tests/capacity/test_capacity.py`에서 `N = U`인 케이스의 폴링·API 합계 기간과 평균 기대값을 새 공식으로 고친다(공식에서 직접 계산).
2. `N = U`이면 폴링 기간이 정확히 `T`인지 확인하는 단언이 있게 한다.
3. `tests/`만 수정한다.

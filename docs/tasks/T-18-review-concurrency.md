# T-18 (review) 동시성 관점 검토

읽기만 한다. 결과는 자기 화면에 남긴다(lead가 transcript로 읽는다). 재현이 필요하면 재현 명령과 기대 결과를 적는다.

## 대상
- `backend/main.py`(홀드·확정·좌석맵), `backend/db.py`(연결 풀: 워커당 10 + 5), `backend/seed.py`, `backend/models.py`, `backend/migrations/`.
- 테스트: `tests/concurrency/`(실제 uvicorn 워커 4개 + PostgreSQL. 동시 홀드 500건, 같은 홀드 동시 확정 20건), `tests/api/`.
- 정리: `docs/concurrency.md`(찾은 결함, 잠금 제거 실험, 홀드 방식 비교, 남긴 방식 A = FOR UPDATE).

## 찾을 것
1. **잠금 없이 읽고 나서 쓰는 곳.** 예: 확정이 홀드를 잠금 없이 읽은 뒤 좌석을 잠그는 순서, 읽은 값에 기대어 쓰는 곳, 트랜잭션 경계 밖에서 읽은 값.
2. **테스트가 아직 다루지 않은 동시 상황.** 예: 홀드와 확정이 동시에, 만료 경계에서의 동시 재홀드, 서로 다른 사용자의 동시 확정, 다른 좌석끼리의 잠금 순서, 풀 대기 시간 초과.
3. **연결 풀 설정의 위험.** 워커 수·`max_connections`와의 관계, 기다리다 시간이 넘었을 때의 응답.
4. `docs/concurrency.md`의 결론(A를 남긴 이유, B의 위험 설명)이 코드와 맞는가.

범위 밖: 여러 좌석 동시 홀드, Redis·대기열.
